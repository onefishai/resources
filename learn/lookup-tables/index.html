Topic 1 — Lookup Tables

Lookup Tables for Multi-Channel Item Names

If you sell through more than one channel, the same item almost certainly has more than one name. Here is how a lookup table brings them all back together.

Introduction

Most independent eateries sell through several channels at once: a point-of-sale system for in-store transactions, one or more delivery platforms, and sometimes a separate online ordering tool or catering portal. Each of these channels keeps its own item catalog, and they rarely agree on names.

A lookup table (LUT) is the simplest tool for solving this. It is a mapping between one canonical name — the name you have chosen as the source of truth — and every synonym that same item goes by elsewhere. Once the mapping exists, it can be applied consistently anywhere you combine data from different sources.

The Problem

The same physical item almost never has the same name everywhere it is sold. Your in-store menu might call it one thing, a delivery platform might list it differently, and another ordering channel might abbreviate or reformat the name entirely.

Individually, each channel's data is accurate. But the moment you try to combine them — to see total sales, total demand, or how one item is performing across your whole operation — the name mismatches break the aggregation. Without reconciliation, what looks like three different items in your reporting might actually be one item sold three different ways.

The Solution

A lookup table has two columns: the canonical name you have defined internally, and the channel-specific name it maps from. Each canonical item can have as many mapping rows as it has name variants across your channels.

The table does not need to be sophisticated. A spreadsheet with two columns works. What matters is that it is maintained consistently and applied every time you combine data from more than one source.

Benefits

  • Accurate cross-channel reporting. Sales and volume roll up correctly under one item, regardless of which channel they came from.
  • More reliable demand forecasting. Forecasting models see the full combined demand signal for an item instead of fragmented partial counts.
  • Less manual reconciliation. Once the mapping exists, it is applied automatically rather than eyeballed spreadsheet by spreadsheet.
  • A single place to update. When a channel renames an item, you update the lookup table once rather than every downstream report that references it.

Real Example

Say you sell a baked good in-store and through two delivery platforms. Each channel uses its own name for the same item:

Canonical NameChannelChannel Name
Blueberry MuffinIn-Store POSBlueberry Muffin
Blueberry MuffinDelivery Platform ABlueberry Muffins (6 pk)
Blueberry MuffinDelivery Platform BBB Muffin — Fresh Baked

All three rows point to the same canonical item, so any report or forecast built on this data sees one "Blueberry Muffin" with combined demand from all three sources.

Walkthrough

  1. Build your canonical item list. Start with the names you already use internally — your menu, your POS, or your own product catalog. This becomes the source-of-truth column.
  2. Gather the channel export names. Pull an item export from each channel you sell through so you can see exactly how each one labels your items.
  3. Match and create mappings. For each channel name, find its canonical match and add a row to the lookup table. Most items map one-to-one; some will have several synonyms across channels.
  4. Handle unmapped items. Anything that does not match an existing canonical name is either a new item or a renamed one. Review these regularly, decide whether they represent something new, and add them to the table.
  5. Apply the table to your reporting. Wherever you combine data from different channels, join it through the lookup table first so every downstream report already sees canonical names.

Best Practices

  • Review unmapped items on a regular cadence. Channels rename and add items more often than you would expect.
  • Keep canonical names stable once chosen. Renaming a canonical item breaks historical reporting continuity.
  • Document channel-specific quirks — packaging counts, abbreviations, seasonal naming — so the next person maintaining the table understands the pattern.
  • Treat the lookup table as a living document, not a one-time setup. New channels and new items mean it never truly stops growing.
