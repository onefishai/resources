Lookup Tables for Multi-Channel Item Names

If you sell through more than one channel, chances are the same item has more than one name. Here's how a lookup table brings them all back together.

The Problem

The same physical item almost never has the same name everywhere it's sold. Your in-store menu might call it one thing, a delivery platform might list it as something slightly different, and another ordering channel might abbreviate or reformat the name entirely.

Individually, each channel's data is fine. But the moment you try to combine them — to see total sales, total demand, or how one item is performing across your whole operation — those name mismatches break everything. Without reconciliation, what looks like three different items in your data might actually be one item sold three different ways.

The Solution

The fix is a lookup table (LUT): a simple mapping between one canonical item name and every synonym it goes by across your channels. You pick one name as the "source of truth," then list every variant that should map back to it.

It doesn't need to be fancy — a spreadsheet with two columns works. One column holds the canonical name, the other holds a channel-specific synonym. Each canonical item can have as many synonym rows as it has name variants in the wild.

Benefits

  • Accurate cross-channel reporting — sales and volume roll up correctly under one item, no matter which channel they came from.
  • Easier demand forecasting — forecasting models see the full, combined demand signal for an item instead of fragmented pieces.
  • Less manual reconciliation — once the mapping exists, it's applied automatically instead of eyeballed spreadsheet by spreadsheet.
  • Catches new variants over time — as channels add or rename items, the lookup table is the one place you update, rather than every downstream report.

Real Example

Say you sell a baked good in-store and through a couple of delivery platforms. Each channel exports its own name for it:

Canonical Name Channel Channel Name
Blueberry Muffin In-Store POS Blueberry Muffin
Blueberry Muffin Delivery Platform A Blueberry Muffins (6 pk)
Blueberry Muffin Delivery Platform B BB Muffin - Fresh Baked

All three rows point back to the same canonical item, so any report or forecast built on this data sees one "Blueberry Muffin" with combined demand from all three sources.

Walkthrough

  1. Build your canonical item list. Start with the names you already use internally — your menu, your POS, or your own product catalog. This becomes the "source of truth" column.
  2. Gather the channel export names. Pull an item export from each channel you sell through (delivery platforms, marketplaces, other ordering tools) so you can see exactly how each one labels your items.
  3. Match and create mappings. For each channel export name, find its canonical match and add a row to your lookup table. Most items map one-to-one; some will have several synonyms across channels.
  4. Handle unmapped items. Anything that doesn't match an existing canonical name is a new or renamed item. Review these regularly, decide whether they're a true new item or just another synonym, and add them to the table.
  5. Apply the table to your reporting. Wherever you combine channel data, join it through the lookup table first so every downstream report and forecast already sees canonical names.

Best Practices

  • Review unmapped items on a regular cadence — channels rename and add items more often than you'd expect.
  • Keep canonical names stable once chosen; renaming them breaks historical reporting continuity.
  • Document channel-specific quirks (packaging counts, abbreviations, seasonal naming) so the next person mapping items understands the pattern.
  • Treat the lookup table as a living document, not a one-time setup — new channels and new items mean it never truly stops growing.
